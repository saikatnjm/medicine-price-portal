# Architecture

See also [DECISIONS.md](DECISIONS.md).

## Phase 1

Next.js 16 (App Router, Server Components) · TypeScript (strict) · Tailwind CSS v4 · local seed data · Docker Compose · Vercel

```
src/app (routes, Server Components)
  ↓ imports `services` from "@/data"
src/services        MedicineService, PharmacyService, FacilityService, DoctorService,
                    LocationService, SpecialtyService, DirectoryService, SearchService
  ↓ depends on interfaces
src/repositories    Medicine*, Generic*, Manufacturer*, Pharmacy*, Price*, Source*
                    Facility*, PharmacyDirectory*, Location*, Specialty*, Doctor*
  ↓ implemented by
src/data/local      createLocalRepositories(dataset) + in-memory search/index
  ↓
src/data/local/seed/*.json   (generated by scripts/data/:
                              - medicines, generics, manufacturers, sources from DGDA
                              - facilities, pharmacies, locations, specialties from OSM)
```

`src/data/index.ts` is the composition root (marked `server-only`): it builds repositories and services and is the only file that changes when the data source changes.

## Rendering

- **Medicine pages:** ~36k render on first request and are cached (`dynamicParams`). Unknown slugs → 404. SEO: indexable when `SITE_INDEXABLE=true`.
- **Directory pages (facilities, doctors, pharmacies):** render on first request and cached. Individual detail pages (by slug) are indexable; list and filtered views are noindex with canonical to the clean path. Unknown slugs → 404.
- **Location/Specialty pages:** render on first request and cached. Indexable if ≥3 related records exist (e.g., /hospitals/dhaka indexable only if 3+ hospitals in Dhaka).
- **Combination pages (e.g., /hospitals/dhaka/cardiology):** noindex if <3 records; canonical to the minimal path (e.g., /hospitals if 0-2 results, /hospitals/dhaka if 0-2 in specialty).
- `/search` and `/search?q=...` are server-rendered from `searchParams`, always noindex with canonical to `/search`.
- API routes: `/api/suggest` for autocomplete (GET, cached 5 min). `/api/*` disallowed in robots.txt.
- The only Client Component is `app/error.tsx` (required by Next.js). All searches and filters work without client JavaScript.

## Future

```
src/app → src/services → src/repositories → src/data/api (ApiRepositories + DTO mappers)
                                              → Django REST API → PostgreSQL
```

The API provider maps DRF responses (snake_case, decimal strings) to domain types. Services and UI stay unchanged.

## Rules

- UI must never import `@/data/local`, seed JSON, repositories or service modules directly (ESLint-enforced). It imports `services` from `@/data` or reads seed data lazily.
- Domain types (types.ts, healthcare.ts, read-models.ts) stay independent of storage and UI frameworks.
- Repository methods are async so network-backed implementations can be drop-in replacements.
- No database, search engine, Redis, authentication or Django in Phase 1.
- Maps use only key-free official URLs and OSM by default; Google Maps Embed API is optional (public key, configured per domain).
- Doctor records are never auto-populated; only verified, consented individuals are added.

## Future Infrastructure

Potential future architecture: Next.js, Django REST Framework, PostgreSQL, Redis, Meilisearch, Celery, object storage, pharmacy integrations. Documented for planning only.
