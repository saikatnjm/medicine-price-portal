# Internationalisation (English + Bangla)

Conventions for adding or changing translated text. Every key must exist in BOTH languages; avoid unused imports.

## Infrastructure already built (do not change it; read src/i18n/*)
- English at unprefixed URLs, Bangla under /bn. All pages live in `src/app/[lang]/…`; proxy rewrites `/x` → `/en/x`.
- `src/i18n/config.ts`: `Locale`, `resolveLocale`, `localizePath(path, lang)` (adds /bn prefix for bn; leaves /api and external URLs alone), `stripLocale`.
- Server components: `import { getT, getLocale, initLocale } from "@/i18n/server"`. `const t = getT();` (reads the request language; no argument needed inside components). Pages: `const lang = await initLocale(params)` as the FIRST thing in the page and in `generateMetadata` (pass lang explicitly: `getT(lang)`).
- Client components ("use client"): `import { useT, useLocale } from "@/i18n/client"`; `const t = useT();`.
- `t("domain.key", { n: 3 })` interpolates `{n}`. Keys are type-checked against `MessageKey`.
- Links: ALWAYS `import Link from "@/i18n/link"` (already swapped repo-wide; it prefixes /bn). For `router.push`, `window.location`, form `action`, or hrefs put in plain `<a>`/JSON-LD/metadata/canonical, use `localizePath(path, lang)` (server: `getLocale()`, client: `useLocale()`).
- Message files: `src/i18n/messages/<domain>.ts`, each `export const <domain> = defineMessages({ en: {...}, bn: {...} })`. en and bn MUST have identical keys (compile error otherwise). Key prefix = domain name (`"home.title"`). You may ONLY edit the message domain files assigned to you (they are registered already in messages/index.ts). Use flat keys, string values. No plural machinery: write separate keys (`x.one`/`x.other`) or phrase with {n}. Numbers stay Latin digits (data, phones and prices are Latin).
- SEO: `pageMetadata({ title, description, path, indexable, lang })` from `@/lib/seo` emits per-language canonical + hreflang alternates; `openGraph(path,title,desc,lang)`, `breadcrumbJsonLd(items, currentPath, lang)`, `websiteJsonLd(lang)`. Pass `lang` everywhere and localise hrefs in JSON-LD with `localizePath`. Titles/descriptions/H1s/FAQ text/breadcrumb names/alt/aria-labels/placeholders/empty+error states must all be translated for bn.

## Rules
- Translate UI text only. NEVER translate or invent data: medicine/hospital/doctor/pharmacy names, addresses, place names, phone numbers, generic names, manufacturer names, DGDA/OSM source names stay as in data. Enum-like labels created by the app (facility kinds, categories, statuses, "Community-mapped", "Unverified", "Sample data" notices, days etc.) must be translated through keys.
- Bangla must be natural, simple, correct, and consistent: ওষুধ (medicine), হাসপাতাল, ক্লিনিক, ফার্মেসি, ডাক্তার, বিশেষজ্ঞ/বিশেষজ্ঞ বিভাগ (specialty), এলাকা/অবস্থান (location), বিভাগ (division), জেলা (district), উপজেলা, থানা, দিকনির্দেশনা (directions), যোগাযোগ (contact), অনুসন্ধান (search), জরুরি (emergency), যাচাই করা হয়নি (unverified), কমিউনিটি-ম্যাপ করা (community-mapped), নমুনা তথ্য (sample data). Keep the medical disclaimer cautious (informational only, consult a doctor/pharmacist). Do not add claims, ratings or facts not in the English text.
- English output must remain EXACTLY as today (existing English tests must still pass). Default language when no provider/holder is English, so tests need no changes unless you change structure. Don't break `vi.mock("next/link")`-based tests.
- Keep changes scoped to your files. Don't touch other agents' files. Don't commit (the lead commits).
- When done, reply with a SHORT report: files changed, new test files, any English strings you deliberately left (and why), anything the lead must wire elsewhere.
- Add/adjust tests only where cheap and safe (e.g. a bn render assertion). Tests live in /mnt/user-data/outputs/repo/tests. Tests that render server components work with default English; to test bn call `setLocale("bn")` from "@/i18n/server" first (reset in afterEach).
